# 🛢️ Нефтекод 2026: Автономный комплекс MES/APC Евро-5

Автономная мультиагентная система управления технологическим процессом производства дизельного топлива ГОСТ 32511-2013 (Евро-5, сера <= 10 мг/кг) в сквозной цепочке:
**ЭЛОУ-АВТ-6 -> Гидроочистка 24-2000 -> Инлайн-блендинг в товарные резервуары**.

Архитектура построена на принципах **децентрализованных двусторонних переговоров** (ADR-13), независимого **Ядра Безопасности** (SafetyKernel, ADR-24), физического цифрового двойника высокой верности (`PlantSimulator` v2) и асинхронного **ИИ-Супервизора** на базе локальной LLM Qwen 2.5 32B / 27B с детерминированным реплеем на кассетах (`REPLAY_STRICT`).

| 6 | **Объяснимость** (причина → действие → ожидаемый эффект → ограничения) | [`src/xai/card.py`](src/xai/card.py), [`src/xai/narrative.py`](src/xai/narrative.py); консоль `/console`, вкладка «Агенты и XAI» |
| 7 | **Воспроизводимость** (запуск по инструкции, повторяемый результат) | Детерминированный реплей `REPLAY_STRICT` на кассетах (`data/llm_cassettes/`); `pytest tests/` — 218+ тестов, все зелёные |

**Допущения не спрятаны.** Каждый технологический предел в системе промаркирован источником — `NORM` (норматив ТЗ/ГОСТ), `DATA` (откалибровано по архиву) или `ASSUMPTION` (инженерная гипотеза с явным обоснованием), и это видно оператору в карточке XAI. Примеры из [`agents/REFERENCE.md`](agents/REFERENCE.md) §3:
- `AVT_T55 <= 386.40 °C` [`ASSUMPTION`] — защитный буфер 5% ниже отсечки закоксовывания печи П-3 (386.4 °C от порога 387.0 °C, история нарушений 0.8%);
- `HT_GOR >= 300 нм³/м³` [`ASSUMPTION`] — минимальная кратность циркуляции ВСГ/сырьё, история нарушений 1.5%;
- буфер по сере блендинга `<= 9.50 ppm` [`ASSUMPTION`] — минимакс-сожаление giveaway вместо жёстких 10.0 ppm ГОСТ, чтобы не переочищать продукт.

## 🌟 Ключевые возможности и инженерные достижения

1. **Абсолютный приоритет безопасности (ПАЗ/ESD > Качество ГОСТ > Экономика)**:
   - Полная изоляция критических барьеров ярусов T0–T3 (29 технологических ограничений с официальным провенансом).
   - 0 допущений нарушений ПАЗ по физической правде установки (`PlantSimulator.truth()`).
   - Истинное соблюдение температуры вспышки ГОСТ (Flash - 2σ >= 55.0 °C, устранение дефекта E10).
2. **Децентрализованные двусторонние переговоры (Bilateral Negotiation)**:
   - Агенты Оптимизации, Надежности, Качества и Снабжения взаимодействуют через совместный квадратичный ремонт (QP Repair, ADR-21) и вычисление Парето-фронта.
   - Устранение «заморозки в нарушении»: при выходе за огибающую оборудования вырабатывается монотонная траектория восстановления (`RECOVERY_ADVISORY`, инвариант I4/I5).
3. **Отказоустойчивость КИПиА и LIMS (DataGuard v2 + Kalman)**:
   - Фильтрация аппаратного клампинга, выявление залипания анализаторов <= 6 тактов.
   - Непрерывный учет старения калибровки LIMS (σ_calib^2(t) = σ_LIMS^2 + q_drift * Δt).
   - Регламентный переход в `REFUSAL_DATA` при одновременном отказе ПАК и устаревании анализа > 24 ч.
4. **Асинхронный ИИ-Супервизор (LLM Supervisor)**:
   - Интеллектуальный анализ трасс решений, генерация сменных брифингов (`ShiftBriefing`) и ответов оператору (`OperatorAnswer`).
   - 100% заземление на факты (`GroundingChecker` с нулевыми галлюцинациями).
   - Двухфакторный валидатор безопасности (`PolicyValidator`): любая попытка ослабления коэффициентов α блокируется.
   - Поддержка локальных LLM через OpenAI-совместимый эндпоинт (vLLM / Ollama) и 100% автономный CI на кассетах.

## 🚀 Быстрый старт (docker)

```bash
docker compose up --build
```

Чтобы задать работу llm, нужно вписать свои данные в docker-compose.yml
```bash
# По умолчанию REPLAY_STRICT — реальный LLM не нужен. Чтобы подключить живую
# модель, экспортируйте эти переменные перед `docker compose up`
- NEFTEKOD_LLM_MODE=${NEFTEKOD_LLM_MODE:-REPLAY_STRICT}
- NEFTEKOD_LLM_BASE_URL=${NEFTEKOD_LLM_BASE_URL:-}
- NEFTEKOD_LLM_API_KEY=${NEFTEKOD_LLM_API_KEY:-}
- NEFTEKOD_LLM_MODEL=${NEFTEKOD_LLM_MODEL:-}
```

### 5. Валидационный отчёт по качеству прогноза (Критерии 1 и 2 ТЗ)

Исследовательский ноутбук `notebooks/01_model_evaluation.ipynb` проверяет, насколько
точно агенты предсказывают показатели качества ДТ, на отложенной по времени выборке
**2025-07-01 … 2026-08-07**. Ноутбук импортирует боевой код (`VakCalculator`,
`StateEstimator`), а не копии формул, — это прямой ответ на критерий «Демонстрация»
(целостный прототип, а не набор несвязанных ноутбуков): валидируется ровно та система,
что идёт на защиту. Ноутбук коммитится с сохранёнными результатами — открыть и
посмотреть можно без запуска. В начале ноутбука — блок «Итог за 30 секунд» со сводкой
для тех, кто просматривает много работ подряд: тезис, найденные и исправленные дефекты,
ключевые метрики и кликабельное оглавление; полный ход проверки — в разделах 1–8 ниже
(вывод каждого — в блоке «Выводы»/«Вывод раздела» в его конце), объёмные code-ячейки
свёрнуты по умолчанию.


Что внутри: метрики 17 формул ВАК против ЛИМС с бутстрап-интервалами, причинно
корректный реплей оценщика состояния (проба подаётся через 24 ч после отбора),
валидация кинетики гидродесульфуризации и колонны стабилизации, анализ остатков,
пересчёт σ и проверка устойчивости к выбросам ЛИМС. Побочные артефакты —
`data/processed/quality_uncertainty.json`, `model_evaluation_summary.json` и
`data/processed/figures/`.

### 6. Запуск полного набора автоматических тестов
```bash
pytest -v tests/
```
Включает 218+ тестов: юнит-тесты модулей, тесты свойств (Hypothesis), регрессии аудита E1–E12, тесты архитектурной изоляции AST, задержка такта p95 <= 2.0 с и LLM-оценка на кассетах.
